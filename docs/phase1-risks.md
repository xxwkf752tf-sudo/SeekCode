# SeekCode 易错点分析与应对思路

## 一、AI 输出格式解析失败

**风险描述**

AI 可能不会严格按约定的 JSON 格式输出，导致命令解析失败。常见表现：

- 输出包含 Markdown 代码块（```json ... ```）
- 字段名拼写错误（如 `commad`、`done` 写成 `finished`）
- 返回纯文本而非 JSON
- JSON 中存在未转义的特殊字符

**影响**

程序无法执行命令，用户看到报错，任务中断。

**应对思路**

1. 在系统提示词中明确要求 JSON 输出，并给出示例
2. 使用正则提取 Markdown 代码块中的 JSON
3. 使用 JSON5 或容错解析器，允许末尾逗号、单引号等
4. 解析失败时，将原始输出作为 `thought` 展示，并提示用户手动确认
5. 记录失败样本，用于后续优化提示词

---

## 二、终端命令执行权限问题

**风险描述**

Windows 上执行命令可能遇到：

- 需要管理员权限（如修改系统目录、安装软件）
- PowerShell 执行策略限制（Execution Policy）
- 杀毒软件或 Windows Defender 拦截
- 命令依赖的环境变量或路径不存在

**影响**

命令执行失败，返回非零退出码或空输出，AI 无法正确继续。

**应对思路**

1. 默认使用 `cmd.exe` 执行，复杂命令可切换到 PowerShell
2. 对需要提升权限的命令提前检测，提示用户以管理员身份运行 seekcode
3. 启动时检测 PowerShell 执行策略，必要时提示修改
4. 执行前检查命令依赖（如 `python`、`git` 是否在 PATH 中）
5. 捕获 stderr 并友好展示，不只是看退出码

---

## 三、历史记忆文件读写冲突

**风险描述**

- 多线程/多进程同时读写记忆文件
- 程序崩溃时记忆文件损坏或为空
- 记忆文件体积无限增长，影响读取速度
- 用户手动修改记忆文件导致 JSON 格式错误

**影响**

上下文丢失、AI 行为异常、程序启动失败。

**应对思路**

1. 使用文件锁或单线程串行化读写操作
2. 写入前先写临时文件，再原子替换
3. 定期备份记忆文件（如 `.memory.json.bak`）
4. 设置记忆文件大小上限，超过时自动压缩或归档旧记录
5. 读取失败时回退到默认空记忆，并提示用户备份已损坏文件

---

## 四、模型切换时的上下文丢失

**风险描述**

自动模式下，判定阶段使用 Flash，执行阶段切换到 Pro。如果切换时只传递部分历史，AI 可能：

- 不记得用户最初的任务目标
- 重复执行已完成的步骤
- 对当前文件状态产生误判

**影响**

任务执行效率降低，甚至出现错误操作。

**应对思路**

1. 判定阶段只发送"摘要 + 标签"，不修改全局对话历史
2. 执行阶段始终发送完整对话历史 + 记忆文件
3. 在记忆文件中维护关键状态（当前目录、已创建文件、最后命令结果）
4. 每次循环开始时由 AI 主动读取记忆文件并确认状态

---

## 五、Token 计算不准确导致成本失控

**风险描述**

- 未统计系统提示词、记忆文件、历史对话的 Token 数
- 自动模式频繁切换模型，实际 Token 消耗高于预期
- 长对话超出模型上下文窗口

**影响**

API 费用增加，请求被截断或报错。

**应对思路**

1. 集成 Token 计数工具（如 `tiktoken` 或 DeepSeek 返回的 usage）
2. 在界面上实时显示本轮请求的预估 Token 数
3. 接近上下文上限时自动压缩或遗忘早期对话
4. 对简单任务坚持使用 Flash，避免不必要的 Pro 调用
5. 提供"重置上下文"按钮，让用户主动清理历史

---

## 六、命令执行超时与死锁

**风险描述**

- AI 生成交互式命令（如 `python` 进入 REPL、`npm init` 等待输入）
- 命令产生大量输出，缓冲区满导致死锁
- 子进程未正确清理，残留后台任务

**影响**

界面卡死，程序无响应，需要强制结束。

**应对思路**

1. 所有命令默认超时 60 秒，可配置
2. 使用非阻塞方式读取 stdout/stderr，避免缓冲区满
3. 执行前拦截已知的交互式命令，提示用户不可执行
4. 超时或停止时强制终止子进程及其子树
5. 在界面上提供"停止当前任务"按钮

---

## 七、危险命令误执行

**风险描述**

AI 可能生成删除文件、修改注册表、下载并执行未知脚本等危险命令。

**影响**

数据丢失、系统损坏、安全风险。

**应对思路**

1. 维护危险命令关键字列表（`rm`、`del`、`format`、`reg delete`、`Invoke-Expression` 等）
2. AI 输出中 `dangerous: true` 时强制二次确认
3. 提供"只读模式"，禁止执行任何修改性命令
4. 默认在用户目录沙箱中执行，避免触及系统关键路径
5. 执行前记录完整命令到日志，便于审计和回滚

---

## 八、前后端通信异常

**风险描述**

如果采用 Python + 本地 Web 服务器方案：

- 端口被占用
- 后端进程崩溃，前端无法感知
- 跨域或本地安全策略限制

如果采用 Electron 方案：

- IPC 消息丢失或顺序错乱
- 主进程阻塞导致界面卡顿

**影响**

界面与执行引擎失联，任务状态不同步。

**应对思路**

1. Python 方案：使用随机可用端口，启动失败时自动重试
2. Electron 方案：将耗时操作放入 worker 线程，避免阻塞主进程
3. 前后端增加心跳检测，断开时自动重连
4. 所有通信添加请求 ID，确保响应与请求对应
5. 前端保存未发送的用户输入，后端恢复后可继续

---

## 九、打包与部署问题

**风险描述**

- PyInstaller 打包后资源路径错误
- 杀毒软件误报 .exe
- 运行时缺少 DLL 或依赖
- 配置文件路径在不同 Windows 版本中不一致

**影响**

用户无法双击运行，体验差。

**应对思路**

1. 使用 PyInstaller 的 `--onefile` + `--windowed` 参数
2. 通过 `sys._MEIPASS` 正确读取打包后的资源文件
3. 配置文件存放到 `%APPDATA%/seekcode`，避免写入安装目录
4. 打包前用 VirusTotal 等工具检查误报情况
5. 提供签名说明和可选的代码签名证书

---

## 十、暗色/亮色模式与字体适配

**风险描述**

- 系统主题切换时界面颜色不协调
- 中文字体在不同系统上显示效果差异大
- 高 DPI 屏幕上字体模糊或布局错位

**影响**

视觉体验不佳，显得不专业。

**应对思路**

1. 使用 CSS 变量管理主题色，支持 `prefers-color-scheme`
2. 中文字体使用系统默认栈（"Microsoft YaHei", "PingFang SC", sans-serif）
3. 使用 `rem` + 相对单位，适配不同缩放比例
4. 在 Windows 上启用高 DPI 感知（Electron 或 PyInstaller 配置）
5. 对极端窗口尺寸做最小宽度和溢出处理
