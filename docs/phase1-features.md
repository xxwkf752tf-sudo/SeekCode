# SeekCode 功能清单与核心流程说明

## 一、产品定位

SeekCode 是一款 Windows 桌面端 AI 终端助手。用户通过自然语言描述任务，由 DeepSeek V4 Pro / V4 Flash 双模型协作生成并执行终端命令，最终完成编程、文件操作、系统维护等任务。

---

## 二、功能清单

### 2.1 用户交互

| 编号 | 功能 | 说明 |
|------|------|------|
| F01 | 任务输入 | 用户在底部输入框以自然语言描述任务，可附带说明文档（拖拽上传或粘贴） |
| F02 | 对话展示 | 中间区域展示用户消息、AI 回复、终端命令及终端输出，支持滚动浏览 |
| F03 | 发送消息 | 点击发送按钮或按 Enter 发送任务；Shift+Enter 换行 |
| F04 | 清空对话 | 可一键清空当前对话上下文（记忆文件保留） |
| F05 | 复制内容 | 支持复制 AI 回复、命令、终端输出中的文本 |

### 2.2 模型与策略

| 编号 | 功能 | 说明 |
|------|------|------|
| F06 | 双模型支持 | 集成 DeepSeek V4 Pro（强能力）与 V4 Flash（快速经济） |
| F07 | 自动模式 | 先用 Flash 对任务做复杂度判定（简单/中等/复杂），再决定后续使用 Flash 还是 Pro |
| F08 | 手动模式 | 用户通过下拉菜单主动选择 V4 Pro 或 V4 Flash |
| F09 | 模式切换 | 界面提供"自动/手动"切换开关 |

### 2.3 Token 优化

| 编号 | 功能 | 说明 |
|------|------|------|
| F10 | 摘要判定 | 自动模式下，判定阶段仅向 Flash 发送简短摘要与历史提纲 |
| F11 | 动态升级 | 判定为复杂任务时，切换至 Pro 并回传完整历史与记忆文件 |
| F12 | 轻量执行 | 简单/中等任务持续使用 Flash，降低 Token 消耗 |

### 2.4 系统提示词

| 编号 | 功能 | 说明 |
|------|------|------|
| F13 | 内置提示词 | 默认系统提示词要求 AI 以指定 JSON 格式输出终端命令 |
| F14 | 提示词编辑 | 用户可在折叠面板或弹窗中查看、修改系统提示词 |
| F15 | 提示词持久化 | 修改后的提示词保存到本地配置，下次启动自动加载 |

### 2.5 终端执行

| 编号 | 功能 | 说明 |
|------|------|------|
| F16 | 命令解析 | 从 AI 返回的 JSON 中解析待执行命令 |
| F17 | 命令执行 | 调用系统 shell 执行命令，捕获 stdout / stderr / 退出码 |
| F18 | 结果回传 | 将终端输出回传给 AI，作为下一步决策依据 |
| F19 | 执行确认 | 对潜在危险命令（如 rm、format、reg delete）可要求用户二次确认 |
| F20 | 执行超时 | 单条命令默认超时 60 秒，可配置 |

### 2.6 记忆管理

| 编号 | 功能 | 说明 |
|------|------|------|
| F21 | 记忆文件 | 本地 JSON 文件保存任务上下文、关键变量、中间结果 |
| F22 | 每次回传 | 每次请求自动附带记忆文件内容，确保 AI 拥有完整上下文 |
| F23 | 记忆读写 | 程序启动时读取、关闭时保存；过程中增量更新 |

### 2.7 交互循环

| 编号 | 功能 | 说明 |
|------|------|------|
| F24 | 循环执行 | AI 根据终端返回结果继续生成命令，直至任务完成 |
| F25 | 完成判定 | AI 输出包含 `done: true` 时结束循环，向用户展示总结 |
| F26 | 异常中断 | 执行失败或用户点击"停止"时中断当前任务循环 |

### 2.8 界面与状态

| 编号 | 功能 | 说明 |
|------|------|------|
| F27 | 顶部标题栏 | 显示应用名称"seekcode"，含窗口控制（最小化/最大化/关闭） |
| F28 | 状态指示器 | 显示当前状态：空闲 / 判定中 / 执行中 / 等待中 / 错误 |
| F29 | 模型状态 | 展示当前实际使用的模型（Pro / Flash） |
| F30 | 暗色/亮色模式 | 支持系统主题跟随或手动切换 |

### 2.9 输出与部署

| 编号 | 功能 | 说明 |
|------|------|------|
| F31 | 生成 .exe | 最终打包为单个可执行文件，无需安装 |
| F32 | 配置持久化 | API Key、默认模型、超时时间等保存到本地配置文件 |

## 三、核心流程说明

### 3.1 自动模式完整流程

```text
1. 用户输入任务
   ↓
2. 将"任务摘要 + 最近 3 轮对话提纲"发送给 V4 Flash
   ↓
3. Flash 返回复杂度标签：simple / medium / complex
   ↓
4. 根据标签选择模型：
      simple/medium → 继续使用 V4 Flash
      complex       → 切换为 V4 Pro
   ↓
5. 将"完整历史 + 记忆文件 + 系统提示词"发送给选定模型
   ↓
6. AI 返回 JSON：{"thought": "...", "command": "...", "done": false}
   ↓
7. 解析命令 → 执行 → 捕获 stdout/stderr/exit_code
   ↓
8. 把执行结果追加到对话与记忆文件
   ↓
9. 如果 done 为 true → 生成总结并结束
   如果 done 为 false → 回到步骤 5 继续循环
```

### 3.2 手动模式完整流程

```text
1. 用户选择模型（V4 Pro / V4 Flash）并输入任务
   ↓
2. 直接将"完整历史 + 记忆文件 + 系统提示词"发送给选定模型
   ↓
3. AI 返回 JSON 命令
   ↓
4. 解析命令 → 执行 → 捕获输出
   ↓
5. 结果回传，循环直至 done 为 true 或用户停止
```

### 3.3 AI 输出格式约定

```json
{
  "thought": "简要说明当前思考，面向用户可读",
  "command": "要执行的终端命令（单行或多行）",
  "dangerous": false,
  "done": false,
  "memory_updates": {
    "key": "value"
  }
}
```

- `thought`：展示给用户看的自然语言说明
- `command`：实际执行的 shell 命令
- `dangerous`：为 true 时弹出二次确认
- `done`：为 true 时表示任务完成
- `memory_updates`：需要更新到记忆文件中的键值对

### 3.4 记忆文件结构

```json
{
  "version": 1,
  "created_at": "2026-08-16T10:00:00",
  "updated_at": "2026-08-16T10:05:00",
  "session_id": "uuid",
  "facts": {
    "project_path": "C:/Users/...",
    "last_command_status": "success"
  },
  "preferences": {
    "default_timeout": 60
  }
}
```

## 四、界面结构

- **顶部标题栏**：品牌名 + 状态指示灯 + 设置入口
- **中部对话区**：消息气泡流，区分用户/AI/系统/终端
- **右侧/底部设置区**：模型选择、自动/手动开关、系统提示词编辑
- **底部输入区**：多行文本框 + 发送按钮 + 附件按钮

---

## 五、非功能要求

- 所有界面文字、代码注释、错误提示使用简体中文
- 模块化代码结构，便于后续维护
- 支持 Windows 10 / 11 单机运行
- 无额外运行时依赖（最终 .exe 自包含）
